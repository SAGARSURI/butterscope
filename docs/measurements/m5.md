# M5 measurements

The device data behind decision record
[0005](../decisions/0005-m5-attach-findings.md), taken from 2026-10-08 to
2026-10-10 on the same Galaxy S24 and iPhone 17 Pro as M2 and M4, with
Flutter 3.47.5 in profile mode.

## Method

`apps/sample/tool/m5/run_tests.sh` runs a test file with
`flutter drive --profile --no-dds --keep-app-running`, `app_test.dart`
unless `TARGET` names another. Each batch starts with one clean warm-up
run that is not counted. The warm-up must draw at 114 Hz or more in every
test of 11 frames or more. On the S24 each run starts only after
`tool/android_ready.sh` passes: the previous app stopped, thermal status
0, the battery at 38 °C or less, power saving off, Stay awake on and at
least 2 GB of memory free. The iPhone's settings are kept by hand.

Each run prints one report as numbered `BSCOPE-REPORT` lines.
`tool/m5/read_report.dart` joins them and fails a run with a missing
chunk, a flush timeout, a build that is not profile, or a span with no
metrics. Every run counted below passed those checks. Semantics are on
in the ordinary tests, as `testWidgets` leaves them, and off in the
harness test.

Span columns are frames / janky % / missed vsyncs / hitch ratio (ms of
hitch time per second of rendering). A dash is a value not recorded for
that run.

## Harness cost

`integration_test/m5_harness_test.dart` runs each test step 50 times,
100 ms apart, in a 5 s span of its own, between an empty span before and
one after. A `Stopwatch` times each call. Three tests run it:

- **Still:** the calibration screen's still window, with a strip below it
  to tap and drag on and a text field nothing listens to.
- **Feed:** the clean Feed. Tap and drag land on the app bar's title,
  which does nothing.
- **Search:** typing into the search field, where each keystroke runs the
  app's search.

A finder searches the tree only when its result is read, so the finder
steps read `evaluate().length`. `tap`, `drag` and `enterText` are async,
so their time can include a frame drawn while they wait. Their span's
lost frames are the measure that counts for them.

`tool/m5/read_harness.dart` pools each step's 250 calls over a phone's 5
runs, and lists the span's janky frames and missed vsyncs in each run. It
refuses a run whose report is unusable or that lacks any call time. Both
phones ran at 61ef8d2: a warm-up and 5 runs each, every run passing with a
whole report.
