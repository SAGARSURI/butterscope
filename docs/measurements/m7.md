# M7 measurements

The device data behind decision record
[0008](../decisions/0008-m7-report-schema-v1.md), taken from 2026-10-13
to 2026-10-16 on the same Galaxy S24 and iPhone 17 Pro as M2 to M6, with
Flutter 3.47.6.

## Method

`apps/sample/tool/m7/run_tests.sh <device-id> <label>` runs a test file
with Butterscope attached, `app_test.dart` unless `TARGET` names another,
in profile unless `MODE=release`. Each batch starts with one clean
warm-up run in profile that is not counted. The phone is readied as in
M6 (`tool/android_ready.sh` on the S24; `devicectl` stops the previous
app on the iPhone).

| | Profile | Release |
| --- | --- | --- |
| Launch | `flutter drive --profile --keep-app-running` | Android: `flutter run --release --no-resident`. iOS: `flutter build ios`, then `devicectl` installs and launches |
| Android log | `adb logcat`, read while the run goes | The same |
| iOS log | `idevicesyslog --no-colors -m 'BSCOPE '`, plus the `flutter drive` transcript | `idevicesyslog` only |

The runner waits for the run's `start` line, then for its last line, and
ends with `butterscope collect` over every log of the run. A run passes
when `collect` writes its file: every line whole and as many frames as
the report counts. `tool/m7/summary.dart` prints each file's identity,
frames and validity.

`LOSS=on` shrinks the S24's log buffer to 64 KB and reads it once, after
the run, so lines are lost on purpose. That run passes when `collect`
names what was lost and writes no file.

(`serious`); their lines arrived whole, so they pass here. The iPhone's
harness release batch ran after a 15-minute cooldown.

## What failed first, and the fixes

| Run | What happened | Fix |
| --- | --- | --- |
| S24 warm-up, c7723e5 | 219 lines printed within 6 ms; logcat and the transcript kept about the first 170. Up to 800 frames lost | The phone pauses 20 ms after every 16 lines (f523c4a) |
| iPhone, before 2b106b2 | `idevicesyslog -p Runner` caught no line: version 1.4.0 matches `-p` only against processes running when it starts | Match the text: `-m 'BSCOPE '` (2b106b2) |
| iPhone app release, 2b106b2 | 1 of 3 runs failed. Report line 12 of 78 was cut after `"Feed scrolls "`; the system log stripped the space and the CRC failed | No report chunk but the last ends in whitespace (1603a0e) |

The pause adds about 0.3 s to an app run and 0.8 s to a harness run,
after the last test.

## Other numbers

- **Lines a run.** iPhone profile: app 207 to 208, harness 720 to 721.
  iPhone release: app 197 to 203, harness 697 to 700. About 80 of each
  are `report` lines; the rest are `frames` lines and the start line.
- **iOS profile.** The system log held every line the transcript held,
  from 2b106b2 on.
- **iOS release.** The transcript held no line, so the system log is the
  only source.
- **Longest line.** 1,067 characters in an iOS release log, a harness
  `frames` line; app runs' longest were 1,043 to 1,049. Report chunks
  of 800 characters arrived whole.
- **Trailing whitespace.** No iOS log line on 1603a0e ends in whitespace.
- **The iPhone.** It read thermal `serious` once at a warm-up on
  2026-10-14, then in the two void runs, and dropped off USB once.
