# M6 measurements

The device data behind decision record
[0007](../decisions/0007-m6-guard-findings.md), taken on 2026-10-11 and
2026-10-12 on the same Galaxy S24 and iPhone 17 Pro as M2 to M5, with
Flutter 3.47.6 (engine 692136cb65) in profile mode.

## Method

`apps/sample/tool/m6/run_tests.sh` runs a test file with
`flutter drive --profile --no-dds --keep-app-running`, `app_test.dart`
unless `TARGET` names another, and passes the app's commit as
`BUTTERSCOPE_APP_COMMIT`. Each batch starts with one clean warm-up run
that is not counted; it must be VALID and flag no rate mismatch. Before
each S24 run `tool/android_ready.sh` checks the phone: thermal status 0,
the battery at 38 °C or less, power saving off, Stay awake on, at least
2 GB free and no third-party app over 300 MB. Before each iPhone run the
runner stops the previous app with `devicectl`, and it will not start
while Xcode is open.

`tool/m6/read_report.dart` checks that each report shows what its run
was set up to show: clean (the run and every span VALID, no rate
mismatch), void by one forced guard and nothing else, or flagged for a
slower screen. `--allow` names a guard that may also void the run; the
iPhone's runs at `fair` used `--allow thermal`, since `fair` voided a run
until 0007.

Identity on every S24 run, apart from a forced field: samsung SM-S921B,
Android 16 (API 36), profile, thermal `none` at start, text scale 0.9
(the phone's own setting), locale en-IN. On every iPhone run: iPhone18,1,
iOS 27.0.1, profile, text scale 1.0, locale en-IN. Every part observed
119.9 to 120.3 Hz unless a row says otherwise.

## Device reads (#34)

`integration_test/m6_device_test.dart` read the phone 10 times, 1 s
apart. The S24 read `samsung SM-S921B`, `Android 16 (API 36)`, thermal
`none` every time; power saving, switched on and off over adb mid-test,
read `true` for the five reads in between. The iPhone read `iPhone18,1`,
`iOS 27.0.1` and thermal `fair` (right after a build on the cable). Low
Power Mode, switched by hand, read `true` for reads 7 to 22 of a 40-read
run.

on real `fair` reads instead, in five runs: three here and the two Limit
Frame Rate runs below.

## Rate mismatch

### S24 switched to Standard mid-run

`settings put secure refresh_rate_mode 0` (Standard, 60 Hz) over adb,
between two Detail tests; the phone's own value, 1 (Adaptive), was put
back after. App commit c4a1fb1.

| Run | Declared | Observed | Result |
| --- | --- | --- | --- |
| switched mid-run | 120 on every part, before and after | 120.0 to 120.2 before, 60.0 to 60.1 after | VALID; every part after the switch flags each judged slice, at 60.0 to 60.2 Hz; none before |
| launched in Standard | 60 on every part | 60.0 to 60.2 | VALID, no mismatch |

### iPhone Limit Frame Rate

Two runs with Limit Frame Rate on, both VOID by `thermal` (`fair`) alone.
The declared rate was 120 at every span's start and end; every span
observed 59.97 to 60.01 Hz and flagged a mismatch over its whole length.
An earlier try with Reduce Motion switched on by mistake drew 120 Hz,
flagged nothing, and was not counted.

No clean run on either phone flagged a slice. The S24's warm-up's first
test, which only launches the app, drew 5 frames at 60 Hz: too few gaps
for a slice, so nothing was judged.
