# 0006: Move to Flutter 3.47.6

- Status: accepted
- Date: 2026-10-10
- Milestone: M5

## Context

The owner's Mac moved from Flutter 3.47.5 to 3.47.6 on 2026-10-10, and
the owner chose to stay on 3.47.6. The repository pinned 3.47.5 in
`.fvmrc`, so the device checkout no longer had its pinned SDK. DESIGN
section 10 names the toolchain, so the pin changes through a record.

What changes between the two releases:

- **The framework and its test packages are identical.** Comparing the
  two SDK downloads, nothing differs under `packages/` (`flutter`,
  `flutter_test`, `integration_test`, `flutter_tools`) except two
  coverage files, and nothing in `dart:ui` or the Dart SDK's libraries.
  `flutter_test` still pins `test_api` 0.7.12.
- **The engine changes only for Windows and the Dart roll.** Between the
  3.47.5 and 3.47.6 tags, five files change: `DEPS` and
  `bin/internal/engine.version`, for Dart 3.13.4 to 3.13.5; one Windows
  engine file; `.ci.yaml`; and `CHANGELOG.md`. The changelog's one entry
  for 3.47.6 fixes a hang in Windows release apps (flutter/192513).
  No Android or iOS engine source changes. Their engines are rebuilt
  with the new Dart VM, though, and the VM's binaries differ.
- **The Dart roll fixes only web builds.** Dart's changelog lists one
  fix for 3.13.5: dart2wasm's tree-shaking removed reachable methods
  with static JS interop calls (dart-lang/sdk#64153). dart2wasm builds
  web apps only, which Butterscope does not support.

Every Flutter source file the docs and code cite, framework and engine,
reads the same in 3.47.6. All of M1 to M5's device data was taken on
3.47.5.

## Decision

1. **Flutter 3.47.6 (Dart 3.13.5) is pinned** in `.fvmrc`, and the
   shared `flutter` constraint is `>=3.47.6`. CI reads the same file.
2. **Source citations name 3.47.6.** The cited files did not change, so
   the claims stand; DESIGN and the code comments now cite the version
   in use. Accepted records 0001 to 0005 and the measurement files keep
   3.47.5, the version their data came from.

## Consequences

- M1 to M5's findings carry over. The framework, the Dart libraries
  and the phone engines' source are the same, and the one Dart fix is
  for the web. The rebuilt Dart VM is the only difference on the
  phones. That it does not change timing is inferred from Dart's
  changelog; no run has compared the two versions.
- The Flutter version is part of a run's identity (DESIGN 7.3), so runs
  on 3.47.5 and 3.47.6 are not comparable. No baseline exists yet, so
  this first matters when M8 takes baselines: each on one version.
- Each phone gets one clean run of the ordinary tests on 3.47.6 before
  the next measured batch, to confirm the rig before M6's work.
- Flutter 3.47.7 is out. A later move follows the same steps: compare
  the releases, record it, and keep each baseline on one version.
